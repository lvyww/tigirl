# 图形安装器生命周期

本设计用于 Inno Setup EXE 安装器。旧 ZIP 的机器级安装入口保持原有行为；两者共用的用户数据初始化支持新的安装基线。

## 程序安装

完整解压 payload。每次运行由 `CoCreateGuid` 生成 32 位十六进制安装编号；包内容哈希仅标识包，不再充当安装目录编号。同版本重装也使用新目录，已有目录或退役清单占用的编号一律拒绝。16 位旧编号只用于识别、恢复和清理既有安装。

校验新版并切换 x64/x86 注册；发布 `install.json` 是提交点。此前失败可以恢复旧版。此后不再记录可回退的 previous，也不会因用户数据初始化或清理失败而恢复旧版。已提交但事务日志归档中断时，恢复流程识别提交编号，不回滚。

成功提交后，所有其他已知版本的原始打包文件按文件、子目录、父目录的顺序登记重启删除。不根据当下文件是否可删除来提前拆除旧版。重启前可能占用多份空间；共享模型、引用计数、选择性解压均未引入。

`retirement.ps1` 按安装清单校验后清理。退役清单先持久保存到 `retired/<编号>.json`，原始 manifest 丢失也能继续清理。清单中的未知哈希、不可读取文件、内容偏离基线的文件保守保留；修改文件另备份至 `preserved`。未列入清单的文件不递归删除。已完成的清单在后续维护时移除。

版本文件标记 `uninsneveruninstall`，避免 Inno 绕过上述保护直接删除。少量卸载脚本单独放在固定的 `maintenance` 目录，不依赖当前版本编号，也不参与重启退役。旧安装器曾跟踪的修改文件另作独立备份，防止其历史卸载日志删除原件。

## 用户文件

`installed-data-baseline.json` 只记录实际成功写入的官方内容哈希。缺失文件安装；当前内容等于基线的文件更新；已修改或无基线文件保留。跳过文件绝不更新或建立基线，即使碰巧等于新版内容。没有基线的旧安装不自动接管，缺失文件按补回处理。

基线文件纳入原有用户事务快照。只有数据合并及初始化成功才发布新基线；失败恢复数据和基线。个人配置、学习记录和其他用户文件不进入程序版本清理。

## 验证

Windows PowerShell 5.1 的隔离回归覆盖数据合并、基线、退役、文件占用、机器事务恢复、注册修复、用户事务和路径边界。重启队列在测试中模拟，不写系统重启任务。`setup_compiler_smoke_test.ps1` 使用固定哈希的 Inno Setup 6.7.3 编译真实安装脚本（小型测试载荷）；另一个只运行 GUID 生成器的探针在初始化阶段立即退出，不执行安装。

```powershell
python tests/setup_resilience_policy_test.py
./tests/setup_data_baseline_test.ps1
./tests/setup_retirement_test.ps1
./tests/setup_compiler_smoke_test.ps1 -Compiler ./build/tools/InnoSetup-6.7.3/ISCC.exe
```

编译和隔离测试不等于实际发布包、多用户、旧应用仍在输入、真实重启后的端到端验收。后者需要 Intel/AMD x64 Windows 测试机，不应在开发者当前输入法环境上无提示执行。
