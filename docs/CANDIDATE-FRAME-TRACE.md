# 候选窗首次显示记录

用于区分隐藏到显示的第一帧，以及随后的内容、注解或布局刷新。诊断开关默认关闭，
不改变现有动画发布规则。需要运行包含此诊断代码的 DLL。

完全退出目标应用，然后在 PowerShell 中运行：

```powershell
.\tools\capture_candidate_frames.ps1 -Application 'C:\Program Files\Everything\Everything.exe'
```

用非敏感测试文字重现，再选词上屏或取消输入。记录自动写到桌面的 `Tigirl-Frames-*`。
单实例应用若转交给已经运行的进程，不会继承开关；开关只作用于脚本新启动的进程。

每个进程最多记录前 3 个 CandidateUI 实例，每个实例最多 32 张成功发布的画面和
8 MiB 像素。超过像素预算仍保留帧元数据，`pixels_saved=0` 表示没有该帧图片。
画面保存为 BMP（半透明部分合成到白底）；包含候选文字，请用测试内容录制。
TSV 不保存原始文字，仅保存长度及用于判断内容是否变化的哈希。

`frames.tsv` 包含毫秒时间、模型/视觉版本、呈现内容哈希、候选数量、可见条目数、
DPI、实际与目标尺寸、是否隐藏到显示、是否首次候选、动画及注解展开状态。
`source` 区分 `layout-final`、`layout-transition`（布局刷新立即发布的过渡帧）和 `timer`。

- `appearing=1`：真正隐藏到显示的成功首帧。
- `first_candidates=1`：首次候选帧，可能此前已显示编码占位窗。
- `layout-transition` 且实际尺寸不等于目标尺寸：新布局在中间尺寸下发布。
- 内容哈希未变而尺寸变化：结合 DPI、模型版本及布局更新继续排查；并不自动代表缺陷。

只在成功发布且仍可见、版本仍有效时捕获；可见期间只复制到有限内存，不写磁盘。
隐藏/销毁时同步输出，不增加线程或永久后台进程。内存复制和隐藏时写盘仍会增加
诊断开销，不能把录制中的精确帧间隔当作未开启诊断时的性能数据。

核对的参考版本：虎爪 `538096b`、虎娘基线 `7aeb445`。
虎爪启动尺寸动画时保留旧图，虎娘立即发布一次起始尺寸的新图；该差异属于可见窗口
更新路径，不能单独证明用户看到的隐藏到显示首帧异常。先收集记录，再决定是否对齐。

## 坐标来源记录

`geometry.tsv` 最多保留 128 次坐标查询，包括被绘制合并的更新。
`frames.tsv` 的 `geometry_sequence` 指向对应查询。矩形字段为 `left,top,right,bottom`。
记录 TSF 原始矩形 `reported`、现有转换结果 `converted`、宿主在逻辑/物理作用域下
的窗口矩形、进入查询前/查询时/宿主窗口的 DPI 感知模式与窗口 DPI。

`gui_*` 记录独立的 Win32 系统光标：`gui_client` 是 GetGUIThreadInfo 返回的
客户区矩形，`gui_screen` 在光标所属窗口的 DPI 作用域内转为屏幕坐标，
`gui_physical` 再转为物理坐标。仅在 `gui_valid=1` 时有参考意义；自绘输入框可能
不提供系统光标，不能把缺失值当作错误位置。这些额外查询只在诊断开关启用时执行。

## 2026-09-12 Everything 副屏跳位定位

本机主屏 175%、副屏 150%。实际记录中，调用线程、查询作用域和搜索框均为
SYSTEM_AWARE，排除本次跳位由回调 DPI 模式切换引起。

搜索框逻辑底边为 -1534。编码占位矩形底边也是 -1534，转换成功，发布位置
为 (701, -1310)。候选到达后 TSF 矩形底边变为 -1532，超出搜索框 2 像素；
`LogicalToPhysicalPointForPerMonitorDPI` 对该端点失败，旧逻辑返回未经转换的
整份矩形，发布位置变为 (826, -1527)。直接调用 API 也复现了框内成功、
框外 2 像素失败、同坐标系顶层窗口成功的行为。

修复按父窗口链重试，仅接受与搜索框 DPI 感知上下文和窗口 DPI 相同的窗口，
每次从原始两个端点重新转换，避免重复缩放。若所有转换失败，则返回无效几何，
不把逻辑坐标当成物理坐标显示。首次候选和动画规则保持原状。

`candidate_host_dpi_probe.cpp` 在各屏幕、各感知模式下覆盖子窗口贴边、底边越界
2 像素、右下角同时越界，以及超出顶层窗口时拒绝无效坐标；预期坐标由顶层窗口
独立转换获得。x64/x86 坐标回归和两套方案的 TSF 回归均通过。
修复安装后，用户在 Everything 副屏前台复测确认：位置正确，无跳动。

## 首次整句候选显示对齐

继续核对虎爪 `538096b` 的 Core 后，确认不能只看 Overlay 的 InputOnly 分支：
`ProtocolHandler.ShouldShowCandidate()` 在候选为空且 `IsSentenceDecodePending`
时返回 false；解码完成回调触发 `PublishUiState()`。`GetPublishedSentenceCandidates()`
在后续解码期间保留上一批候选。Overlay 收到可见状态后，隐藏到显示直接发布完整几何。
因此首次整句结果尚未就绪的编码状态通常根本不应进入可见的 InputOnly 分支。

虎娘对应在刷新前检查引擎是否仍在等待当前整句结果；无候选且结果未就绪时保持隐藏，
结果到达后按现有首次发布路径显示。已完成但为空的结果仍允许显示编码。没有新增
等待时长、定时器、线程或同步等待。此条件不影响普通字词模式的空码反馈。

验证：真实候选窗口和渲染器回归通过（34 个场景、991 项检查）；用户本机前台测试通过。

## Firefox 提前上屏后的续写闪动

用户报告地址栏输入 `vuj`，提交“这”并保留 `j` 时偶发露出宿主背景。
回归场景用真实引擎执行提前上屏：原候选被全部提交，投影后的候选列表为空，
剩余 `j` 仍在解码。修复前真实窗口测试稳定失败于
`Pending suffix hid or shrank a published candidate window`：首次隐藏条件也命中了
已经显示候选的续写阶段。若完成结果在绘制前到达，则中间空状态被合并，因而不闪。

修复保留首次无结果时隐藏的规则；已经发布过候选、窗口可见且光标有效时，
待解码的空列表保留现有画面，停止旧动画并清除鼠标命中区域。完成结果驱动下一次
刷新；无固定等待、无新定时器。真正空结果、取消、失焦和布局丢失仍走原有处理。
这项回归验证了显示路径的因果关系；Firefox 前台是否还存在其它隐藏原因需实测。

修复后候选窗回归通过：36 个场景、1069 项检查；ARM64X/x86 本机构建通过。

Firefox 本机自动前台验证：重启后的 Firefox 确认加载修复 DLL，临时新标签页通过
SendInput 输入，30 轮全部确认地址栏 `vu` → `这j`；`u` 到 `j` 间隔轮换
40/80/120/220 ms。监听候选 HWND 显示/隐藏/销毁/位置事件，并在按下 `j` 后
约 450 ms 内累计取得 1072 次窗口采样：无隐藏、销毁、缺失或异常缩小，最小
尺寸 138×73 物理像素。校准截图确认候选窗显示 `j`。测试结束关闭临时标签页，
未提交搜索。该验证覆盖窗口可见性与几何，不等同于逐帧桌面合成录像。
