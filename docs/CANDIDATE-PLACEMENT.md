# 候选窗：底部空间不足时上移，不再上翻

## 定位规则

使用光标所在（或最近的）显示器的 `MONITORINFO.rcWork`，不是主屏幕尺寸，也不是整个 `rcMonitor`。坐标与候选尺寸均为物理像素。

- 空间足够：窗口顶边在 `caret.bottom + 5`，保留原有光标间距。
- 下方空间不足：窗口上移至 `work.bottom - height`，底边贴工作区底边，不再贴光标上沿。
- 顶部、左右越界仍进行约束；保留右边 2 像素余量，取消旧的底边 2 像素余量以精确对齐工作区底边。
- 超高/超宽窗口仍以工作区左上界兜底，不因上下界倒置调用无效的 `clamp`。本改动不新增滚动、缩字或候选截断。

`placeCandidateWindow()` 是无状态函数。移除了 `above_` 及候选 UI 的定位状态、显示器缓存与重置分支。字词模式频繁提交、整句模式持续组合、窗口缩小、工作区改变，都按相同规则处理。

这是“上移”，不是“始终显示在输入行上方”：空间紧张时可以与输入行重叠。任务栏自动隐藏时遵循 Windows 返回的工作区，不猜测任务栏高度。

## 保持不变

首次非空候选成功发布后才记录已呈现；首次出现仍直接完整显示。已有候选的尺寸变化及注解展开沿用原动画和时长。仅布局变化不重建候选模型，不覆盖宿主选择或分页。QQ 短暂布局丢失的保留/恢复、真正超时隐藏、延迟计时、鼠标命中、提交/取消及迟到消息处理均保持原路径。

没有新增配置、线程、定时等待、跨组合全局状态，也没有改动安装器、输入规则、码表或解码器。

## 回归

在 MSVC Developer PowerShell 中运行：

```powershell
python tests/candidate_ui_presentation_test.py --negative-control --placement-negative-control
```

`candidate_placement_math.h` 覆盖正常放置、刚好容纳、溢出 1 像素、高度连续变化、缩小、左右与负坐标工作区、四种 DPI 对应物理尺寸、任务栏四边工作区及超大窗口。

`candidate_ui_placement_cases.h` 复用真实窗口/DirectWrite/Direct2D/分层窗口发布探针，覆盖横竖排底部首帧、后续增长与缩小、首帧发布失败重试、布局暂失恢复、候选与注解延迟，以及 0/100/200 ms 设置下 1/2/5 候选的连续字词提交。鼠标选词使用移动后窗口的真实客户区命中位置；排队消息不能在提交后复活旧窗口。

新增负向对照仅在临时 C++ 副本中恢复“溢出则放到光标上方”，保留首次呈现和内容/布局分离修复，要求在指定底边断言失败。编译/链接失败不算检出原问题。

测试中的注册/TSF 宿主、时钟及定时器投递是替身，数学用例中的多显示器工作区是合成坐标。不得将 CI 结果等同于真实 QQ/微信、物理多屏多 DPI、自动隐藏任务栏、ARM64/ARM64X 验收。现有动画分别对位置和尺寸取整，中间帧允许原有 1 物理像素取整误差，最终帧底边精确对齐工作区。
