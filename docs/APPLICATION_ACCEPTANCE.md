## 执行与记录

使用新建空白文档或独立浏览器测试页面，不操作已有工作文档。选择“原生虎码”、
内置虎码字词、默认中文和默认选择键。记录配置；非默认选择键或调频数据会改变
下列预期。浏览器页面为 `tests/application_input.html`，可导出本页事件记录。

| 操作 | 应核对的结果 |
|---|---|
| 输入 `ab`，按空格 | 组合显示及候选正常；只提交一个“交” |
| 输入 `dk`，按空格 | 只提交一个“口” |
| 输入 `ab`，按 2 | 默认码表及未调频状态下提交“疒” |
| 输入 `ab`，按 Escape | 删除当前预编辑，保留此前提交的正文 |
| 输入 `ab`，退格一次，再补 `b` | 组合和候选跟随编码变化，无重复正文 |
| 输入 `ab` 后切到另一输入区域，提交 `dk`，再返回 | 各区域正文独立；已被应用终止的组合不得复活 |
| 输入 `ab`，鼠标选择候选 | 恰好提交所选词；焦点与后续键入仍在编辑区域 |
| Shift 切换中英文，再切回；Ctrl+空格切换 | 模式指示、实际键入一致，修饰键不粘滞 |
| 多行输入、滚动、移动窗口 | 候选跟随当前插入点，无旧位置残留 |
| 打开设置/方案管理再关闭 | 回到原编辑区域；后续键入正常 |

逐项记录实际文本、组合事件及异常，不以输入框中最终“看起来正确”替代过程检查。
输入事件导出不能证明候选排版、鼠标命中或视觉定位，需另保存截图/观察记录。
字体、横竖排和不同 DPI 的检查沿用 `PLAN.md` 的完整要求。

`registered_tsf_test.py --interactive` 现在要求默认桌面、有效前台窗口及至少
15 秒键鼠空闲才启动。此条件不能保证运行期间无人输入。

测试期间若出现额外输入、焦点被其他应用夺走或初始文档非空，保留诊断并把该轮
标记为受干扰，不作为通过证据；也不能据此自动排除已有产品故障。
系统按键注入与真实硬件按键分别记录。测试宿主、浏览器事件页及文件盘点都不能
单独证明整个实际应用矩阵通过。
