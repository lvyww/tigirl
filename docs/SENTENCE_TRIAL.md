# 整句试用验收

开发包实现纯原生 TSF 整句输入，不包含 Qwen 或常驻 Core。当前开发包已通过
模型/解码器对照、八组真实码表引擎对照、包内默认模型的三架构 TSF 检查，
以及实际控件在 100%/150%/200% 缩放下的绘制检查。已安装版本 `56502c3a10a47997`，三架构标准 Rich Edit 前台普通输入检查通过；
真实应用的整句体验仍待验收。

## 安装与恢复

在项目目录运行：

```powershell
.\install_arm64.ps1 -Arm64X -CheckOnly
.\install_arm64.ps1 -Arm64X
.\install_x86.ps1 -CheckOnly
.\install_x86.ps1
```

先安装主包，再更新32位补充组件。安装会请求 Windows 管理员权限，并保留旧版本。
更新后需彻底退出并重新打开测试应用，让它们加载新 DLL。主安装与32位组件
分别记录在 `build/native-install.json`、`build/native-install-x86.json`。
旧主安装快照和回退命令见 [安装文档](INSTALL.md)；回退主版本后，需同步核对
32位注册和对应安装记录，不能将新旧组件混合视作完成回退。

## 应用测试

1. 在方案管理中选择现有虎爪码表根目录，再使用“虎整句”方案。
   首次选择会由短时导入工具准备共享资源。
2. 在 ARM64 编辑器、微信、Word、32位 Pain 打器中分别按正常节奏输入熟悉的句子。
   检查候选、空格提交、选重、退格、取消和标点，确认没有重复或丢失文字。
3. 在“输入设置 → 整句输入”启用自动提前上屏、设置最少保留编码为3，再输入一段文字。
   检查已提交前缀与后续文本的衔接，暂停输入时不应自行追加文字。
4. 带着未完成编码切换应用或中英文状态，再继续输入；检查旧候选不会出现在另一窗口。
   Ctrl+空格应只切换一次。
5. 修改用户词后重新输入，切换方案再返回，检查修改可见且普通字词方案仍正常。

记录每个应用的架构、是否确实加载新版本，以及观察到的延迟或差异。自动测试不能替代
这些实际应用反馈。前台自动按键测试需要用户在场；不要向用户正在编辑的文档注入测试文字。

## 已知性能范围

隐藏真实 TSF 宿主的三轮测量中，30毫秒逐键输入后的128码空格提交约为
ARM64 19毫秒、x64 27毫秒、x86 30毫秒；不留间隔快速输入128码后立即提交
约为132/167/310毫秒。长码快速提交仍可能有明显等待，尤其是32位应用。
这些是固定样本测量，不是所有应用的延迟保证。详见
[整句性能记录](SENTENCE_PERFORMANCE.md)。
