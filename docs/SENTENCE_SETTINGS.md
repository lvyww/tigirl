# 整句输入设置（开发版）

从“输入设置 → 整句输入”配置非神经整句功能。此页已加入开发版管理器，
尚未更新当前安装版本；模型已加入开发包，前台验收仍在进行。

| 设置 | 默认值 | 用途 |
| --- | --- | --- |
| 方案名称包含“整句”时自动启用整句模式 | 开启 | 对名称包含“整句”的方案启用整句输入；还需要可用的模型和方案资源。 |
| 自动提前上屏已确定的句子前缀 | 开启 | 根据原版的自动上屏判断，将确定的前缀提交，继续输入剩余部分。 |
| 自动选重最低码数 | 3 | 0 禁用；1–128 表示词条编码至少达到该码数，才允许不输入选重键参与组句。显式选重及首位词条不受此门槛影响。 |
| 提前上屏后最少保留编码 | 0 | 可填 0–32，控制自动上屏时保留的未提交编码数量。 |
| 仅使用最优码组句的高频字数量 | 1500 | 排名前若干的高频字只使用最优码参与组句；0 关闭此限制。 |
| 允许全码组句的例外字符 | 原版默认白名单 | 填写不受高频字最优码限制的字符，可明确清空。 |

配置只读取 `自动选重最低码数`；未配置取 3，不读取或迁移旧的布尔选项。非首位多字词仍需显式选重，完整输入的候选列表保留以供手动选择。

整句模式的数字选重键复用 `自定义选重键.txt` 的当前映射。比如 `2选 0x32 0x39`
允许主键盘 2、9 都指定当前码段的第二选；重复绑定仍以较小选位优先。
数字进入编码时只转换一次，因此输入 `t9` 后编码和 Enter 原码输出均为 `t2`，
退格删除的是标准选位后缀。这是指定码表选位，不是选择候选窗口中的第二条整句。
第十选规范化为 `0`；未绑定数字保持原有数字选位，小键盘按自身键码独立查询。
Shift/Ctrl/Alt/Win 组合键、空闲数字、分号和引号沿用原有路由。
映射刷新作用于后续按键，不重新转换已有编码；设置页显式请求清空组合的行为仍保留。

专项回归：`python tests/sentence_digit_bindings_test.py`（MSVC 开发环境加 `--cxx cl`），
或构建 `tests/SentenceDigitBindingsProbe.vcxproj`。测试覆盖实际 Engine 与解码器的编码、
候选和提交，以及重载、Tab 锁定、提前上屏续输和普通/整句模式切换。
独立程序也可接收三个只读参数：整句 `.sentence.tcd`、Q8 五阶模型、自定义选重文件，
验证第二选绑定 9 时 `t2`/`t9` 均提交“我们”。这些自动测试不代表实体键盘验收。

点击“保存”后写入当前用户配置，并发送现有的设置刷新标记。与其他输入设置
一样，刷新会清除未完成编码并应用默认中英文状态。点击“取消”不保存修改。
未改动的配置项不重写，因此其他进程在窗口打开期间修改的无关设置会保留。

此页不包含 Qwen、模型服务器或神经重排设置。模型路径仍采用安装目录下的
`Models/sentence-fivegram-mobile.bin`；已有的 `整句语言模型` 配置覆盖值会保留。

验证记录：`build/input-settings-arm64.json`。测试使用独立、未激活的桌面，
覆盖保存和重新打开、取消、显式空白名单、12种非法参数，以及 96/144/192 DPI
控件边界检查。已检查 `build/sentence-settings-96.png`、
`sentence-settings-144.png`、`sentence-settings-192.png` 中的实际控件绘制：
标签和按钮无重叠、输入框显示数值，白名单使用可横向滚动的单行输入框。
截图通过控件的 WM_PRINT 绘制；没有切换用户的输入桌面，不代表跨屏拖动验收。
